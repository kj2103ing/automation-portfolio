01. 공통 AD 변환 Function Block · AD_Conv

MELSEC Q64AD의 아날로그 입력값을 실수형으로 변환하고 센서별 스케일을 적용하는 공통 FB입니다. HMI 표시용 정수 PV 변환, 설정값(SV) 초과 판정, 입력값이 K-50 미만일 때의 센서 이상 판정을 하나의 블록으로 구성했습니다.

AD_Conv 공통 FB · 레더 처리 원리

아래 내용은 프로젝트에서 확인된 기능을 처리 단계별로 풀어 쓴 해설입니다. 실제 레더의 개별 명령어 배치와 명령 순서는 위 원본 이미지를 기준으로 확인해야 합니다.

01 · 아날로그 입력 수신

Q64AD의 채널별 디지털 변환값을 PLC D0~D3에 저장하고, 해당 채널의 값을 공통 FB에 전달합니다.

02 · 자료형 변환

정수 형태의 A/D 입력을 실수 연산에 사용할 수 있는 형태로 변환합니다. 이 과정이 필요한 이유는 센서의 측정 범위를 비율로 환산하기 위해서입니다.

03 · 센서별 스케일 적용

센서에 맞는 스케일 정수를 사용해 입력값을 공학 단위의 현재값(PV)으로 환산합니다. 같은 FB를 사용해도 채널별 스케일은 달라질 수 있습니다.

04 · HMI 표시값 생성

환산된 PV를 화면 표시 형식에 맞게 변환합니다. 실수 PV 주소와 표시용 정수 주소는 서로 다른 용도입니다.

05 · 설정값 초과 판정

PV와 설정값(SV)을 비교해 센서별 초과 알람 비트를 처리합니다. 예를 들어 온도 채널은 M10, 압력 채널은 M12입니다.

06 · 센서 이상 판정

프로젝트의 FB 설명 기준으로 입력값이 K-50 미만인 조건을 센서 이상으로 판정합니다. 초과 알람과 별도 비트로 구분하며, 온도 M11, 압력 M13 등이 해당합니다.

설계 의도: 공통 FB의 연산 로직을 재사용하면서 센서별 입력·스케일·SV·알람 디바이스만 구분하면, 동일한 처리 방식으로 4개 아날로그 채널을 관리할 수 있습니다.

02. 센서별 공통 FB 적용

같은 AD_Conv FB를 온도·압력·유속·전류의 각 채널에서 호출하고, 채널별 입력 주소·스케일·설정값·알람 비트를 구분했습니다. 각 이미지를 클릭하면 원본 레더를 확인할 수 있습니다. 아래의 주소·판정 흐름은 실제 프로젝트에 기재된 PLC 디바이스를 기준으로 정리했습니다.

센서별 레더를 읽는 순서

① Q64AD 입력 D0~D3② 공통 AD_Conv FB 호출③ 센서별 PV 환산 D80~D86④ SV 비교 및 알람 비트 M10~M17⑤ HMI · Node-RED 상태 표시

PV는 현재 계측값, SV는 비교 기준 설정값입니다. 센서 초과 알람과 센서 이상 알람은 서로 다른 비트로 관리합니다. 아래 이미지는 실제 레더 캡처이며 설명은 이해를 돕기 위한 요약입니다.

MELSEC CH3의 아날로그 유속 계측과 구분되는 Siemens 펄스형 유량 센서 제어입니다. Network 1~4를 제어 순서대로 배치했습니다. 각 Network의 역할과 데이터 흐름을 설명하며, 실제 명령어·주소·상수는 원본 레더 이미지를 기준으로 확인해야 합니다.

Network 번호는 프로그램의 구성 순서입니다. 위 요약은 기능별 관계를 나타내며, 모든 Network가 단일 직렬 신호선으로 연결된다는 뜻은 아닙니다.

Network 1 · 밸브 및 램프 제어

밸브 출력 및 유량 표시 램프 제어 회로

읽는 순서

밸브 조작 조건을 확인하고 실제 밸브·표시 램프의 출력 회로를 따라갑니다. 명령 비트와 물리 출력 피드백은 구분해서 확인해야 합니다.

현장 의미: 조작 명령이 전달되었다는 사실만으로 밸브가 실제로 동작했다고 판단하지 않도록 출력 상태를 함께 감시합니다.

Network 2 · 고속 카운터 및 펄스 계측

유량 센서 펄스 카운트 수집과 초기화

읽는 순서

유량 센서의 펄스 입력 → 카운터 계측값 → 초기화 조건 순서로 확인합니다. 이 단계의 카운트값은 아직 최종 유량 표시값이 아닙니다.

현장 의미: 펄스형 센서의 입력 변화가 PLC 내부 계측값으로 집계되는 과정입니다. 초기화 명령과 계측 데이터의 관계도 함께 확인합니다.

Network 3 · 유량 환산 연산

카운트값의 실수 변환과 TURN 유량 기반 환산

읽는 순서

Network 2에서 얻은 카운트값을 연산 가능한 자료형으로 변환하고, 프로젝트의 TURN 유량 기준을 적용하는 계산 부분을 확인합니다.

현장 의미: 펄스 개수 자체가 아닌 유량 단위의 수치를 만들기 위한 연산 단계입니다. 정확한 환산식과 상수는 원본 레더의 명령어·피연산자를 기준으로 확인해야 합니다.

Network 4 · HMI 표시값 변환

계산 결과의 정수·실수 데이터 변환

읽는 순서

Network 3의 계산 결과가 HMI에서 사용할 자료형과 표시값으로 변환되는 과정을 확인합니다. 계측값·연산값·표시값은 역할이 다를 수 있습니다.

현장 의미: PLC 내부의 수치와 HMI 화면의 자릿수·단위가 일치하도록 데이터 표현을 맞추는 단계입니다.

04. MELSEC · 유량 환산 및 누적유량

CH3 유속 계측값과 전자밸브 개폐시간을 이용해 환산유량을 계산하고, 누적유량을 적산하는 별도 레더입니다.

유량 계산 · 누적유량 및 초기화

D24 유속 PV, D40 밸브 개폐시간, D44 환산유량, D48 누적유량을 사용하는 연산 회로

유량 계산 레더 · 단계별 해석

① 유속 현재값 확인

CH3의 계측값을 스케일 변환한 유속 데이터를 연산에 사용합니다. 이 회로 설명에 기재된 D24는 표시용 변환값이며, 센서별 FB 설명의 실수 PV D84와 구분해야 합니다.

② 밸브 개폐시간 확인

D40에 저장된 밸브 개폐시간을 계산에 반영합니다. 밸브 동작시간이 유량 환산에 어떤 방식으로 적용되는지는 원본 레더의 연산 명령어를 기준으로 판단합니다.

③ 환산유량 계산

유속 계측값과 시간 정보를 사용한 계산 결과를 D44 환산유량으로 관리합니다. 환산식의 계수와 단위는 원본 연산식을 확인해야 합니다.

④ 누적유량 적산

계산된 유량을 누적하는 결과 데이터가 D48입니다. 환산유량은 해당 계산의 결과이고, 누적유량은 시간에 따라 합산된 값이라는 차이가 있습니다.

⑤ 초기화 조건 확인

초기화 회로에서는 리셋 조건이 성립했을 때 어느 디바이스를 0으로 만드는지 확인해야 합니다. D44와 D48이 모두 초기화되는지는 원본 레더의 실제 초기화 대상 주소를 기준으로 판단합니다.

확인 기준: 이 설명은 포트폴리오에 기재된 데이터 주소와 기능 흐름을 해설한 것입니다. 개별 명령어, 적산 주기, 초기화 접점과 연산 계수는 레더 이미지를 확대해 대조하기 전까지 단정하지 않습니다.

05. MELSEC · 전력 계산 및 전력량 적산

CH4 전류 계측값을 이용해 전력과 전력량을 계산합니다. 전압 224.5 V와 역률 0.95는 레더에 기재된 적용값입니다.

전력 계산과 전력량 적산의 차이

① 전류 계측

CH4 전류 센서의 측정값을 PLC에서 환산하고, 전력 연산에 필요한 자료형으로 처리합니다.

② 유효전력 계산

레더에 기재된 적용 전압 224.5 V와 역률 0.95를 사용해 전력을 계산합니다. 단상 유효전력의 기본 관계는 P = V × I × PF입니다. 실제 연산의 단위와 저장 주소는 원본 레더를 기준으로 확인합니다.

③ 시간 단위 환산

전력(W)은 특정 순간의 소비 속도이고, 전력량(Wh)은 시간에 따른 누적 소비량입니다. 1초 간격의 전력값을 Wh로 적산할 때는 일반적으로 W ÷ 3600을 사용합니다.

④ 주기별 적산

프로젝트 설명의 SM412 1초 클럭을 이용한 누적 연산을 확인합니다. 클럭 접점의 동작 방식과 실제 가산 조건은 원본 레더에서 대조해야 합니다.

검토 포인트: 224.5 V와 0.95는 이 프로젝트에서 적용한 값이지 모든 설비에 공통인 상수가 아닙니다. 위 W ÷ 3600은 1초 샘플을 Wh로 환산하는 일반 원리이며, 원본 레더가 정확히 같은 연산을 사용하는지는 별도 확인이 필요합니다.

01. 센서 데이터 저장 · INSERT

온도(temperature), 압력(pressure), 유속(lpm), 순간유량(liter), 전류(ampere), 원격 AD(ad_val)를 Flow Context에서 가져옵니다. 값이 하나라도 undefined이면 INSERT를 중단합니다.

INSERT INTO sensor_db.node_sensor
    (temp, pressure, lpm, liter, ampere, ad_val)
VALUES
    (${temp}, ${pressure}, ${lpm},
     ${liter}, ${ampere}, ${ad_val});

02. 데이터 이력 조회 · SELECT

조회 기간은 15분·30분·1시간 중 선택하고, 표시 개수는 20·50·100건 또는 전체(최대 1,000건)입니다. 실제 Function에서 기간과 LIMIT를 허용 값으로 제한해 쿼리를 생성합니다.

SELECT
    no,
    date,
    temp,
    pressure,
    lpm,
    ampere,
    liter,
    ad_val
FROM sensor_db.node_sensor
WHERE date >= NOW() - INTERVAL ${interval}
ORDER BY date DESC
LIMIT ${limit};

03. 조회 결과 분기 · 테이블 + 차트 6개

MySQL SELECT 결과는 최근 조회 데이터 UI와 이력 트렌드 가공 Function으로 동시에 전달됩니다. 차트는 조회 결과의 역순 정렬(DESC)을 시간순으로 뒤집어 온도·압력·유속·전류·순간유량·원격 AD로 분리한 뒤, action: "replace" 방식으로 갱신합니다.

     alarm_state, event_time)

     ${state}, NOW());

02. 작업자 조치 완료 · ACK UPDATE

UPDATE sensor_db.alarm_history
SET
    ack_state = 1,
    ack_time = NOW()
WHERE no = ${no}
  AND alarm_state = 1
  AND ack_state = 0
  AND EXISTS (
      SELECT 1
      FROM (
          SELECT alarm_key, event_time
          FROM sensor_db.alarm_history
          WHERE alarm_state = 0
      ) AS recovery
      WHERE recovery.alarm_key =
            sensor_db.alarm_history.alarm_key
        AND recovery.event_time >
            sensor_db.alarm_history.event_time
  );

03. 알람 이력 및 당일 처리 현황

MySQL의 최근 20건을 no DESC로 조회해 발생·복구·ACK 여부·조치 시각을 Dashboard에 표시합니다. 당일 발생 건수, 조치 완료 건수, 미조치 건수도 별도 SQL로 집계합니다.

설비 알람의 ON/OFF 변화(발생·복구)와 작업자의 ACK(조치 완료 기록)는 구분됩니다. ACK SQL은 동일 알람 키에 대해 해당 발생 시각보다 나중의 복구 기록이 있는지 검사합니다.

03. 제어 명령과 상태 피드백의 차이

Dashboard에서 버튼을 눌러 WRITE 명령을 전송한 것만으로 설비 동작을 확정하지 않습니다. MELSEC의 Y10, Siemens의 Q0.2처럼 PLC 출력 상태를 별도로 읽어 화면에 반영합니다. 유량 초기화 명령은 두 PLC 모두 약 300ms 펄스를 전송하도록 Function에서 처리합니다.

Dashboard의 표시값은 PLC 통신으로 수신한 데이터에 기반하며, 실제 밸브 기계 동작 확인과 출력 비트 상태 확인은 구분됩니다.

MySQL 데이터베이스 설계

센서 이력과 알람 이력을 별도 테이블로 관리하며, 알람 조치 완료 기능을 추가하면서 ACK 컬럼을 확장했습니다.

node_sensor · 센서 데이터 테이블
CREATE TABLE sensor_db.node_sensor (
  no INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  temp FLOAT(5,2),
  pressure FLOAT(3,2),
  lpm FLOAT(5,2),
  liter FLOAT(5,2),
  ampere FLOAT(3,2),
  ad_val FLOAT(5,2),
  date DATETIME DEFAULT CURRENT_TIMESTAMP
);
alarm_history · 알람 이력 및 ACK 확장
CREATE TABLE sensor_db.alarm_history (
  no INT AUTO_INCREMENT PRIMARY KEY,
  alarm_key VARCHAR(50) NOT NULL,
  alarm_name VARCHAR(50) NOT NULL,
  alarm_event VARCHAR(10) NOT NULL,
  alarm_state BOOLEAN NOT NULL,
  event_time DATETIME NOT NULL
);

ALTER TABLE sensor_db.alarm_history

실제 Function에서 사용한 SQL

조회 기간·표시 개수·센서값·알람 식별자는 Function에서 생성되는 값입니다. 아래 SQL은 가독성을 위해 일부 구문을 축약했으며, 알람 ACK는 후속 복구 이력을 검사한 뒤 갱신합니다.

센서 데이터 저장 · INSERT
INSERT INTO sensor_db.node_sensor

  pressure,
  lpm,

  ampere,
  ad_val)

SELECT no,
  date, temp,
  pressure,
  lpm,
  ampere,
  liter,
  ad_val

WHERE date >= NOW() - INTERVAL ${interval}
ORDER BY date DESC
LIMIT ${limit};
